# Bunny → 异世界连接：迁移计划

## 迁移原则

1. 原始 `bunny-original.html` 永不直接修改。
2. 每次只迁移一个可独立验证的模块。
3. 数据先定义兼容层，再改变存储结构。
4. 新版每个阶段都必须能够启动和返回桌面。
5. 先保持行为一致，再改善功能与视觉。

### Phase 5：异世界连接核心

当前进度：

- 已将“微信”入口升级为真实 AI 聊天窗口

- 可配置接口地址、API Key、模型、温度、最大输出与流式回复

- 可选择当前角色与预设
- 世界书支持始终读取、关键词触发和手动启用
- 会检查全局、角色与模块适用范围
- 会按优先级及注入位置组合角色、预设和世界书
- 发送消息时会把上下文和聊天历史一起交给模型
- 支持流式显示、停止生成、错误提示和清空聊天
- 每位角色拥有独立的本地聊天记录，刷新后仍可恢复

### Phase 6：记忆宫殿

当前进度：

- 已建立以角色 ID 隔离的长期记忆库
- 支持重要事件、关系变化、用户偏好、承诺约定、未完话题和其他分类
- 支持标题、正文、关键词、重要程度、置顶与启用状态
- 支持创建、编辑、分类筛选、停用、置顶和删除
- 记忆按照置顶、重要程度和更新时间排序
- 当前记忆库选择与所有记忆都保存在本地
- 已支持按用户设置的聊天轮数自动调用模型整理记忆
- 已支持在聊天连接设置中手动立即整理
- 提取结果经过 JSON 校验、分类修正和重要程度限制
- 相同标题或正文的记忆会合并更新，不重复创建
- 当前消息会按关键词、正文、标题、重要程度和置顶状态检索相关记忆
- 仅将排名靠前的相关记忆注入本次聊天上下文
- 已增加可选的 OpenAI 兼容 Embedding 接口与模型设置
- 已使用 IndexedDB 为每位角色保存本地向量索引
- 新建或编辑记忆时只更新变化条目，不会每次重算全部记忆
- 已采用关键词分数、向量相似度、置顶和重要程度共同排序
- 向量服务失败或尚未配置时自动退回原有关键词检索

后续扩展：

- 为自动记忆增加审核队列与批量管理
- 增加索引状态统计、模型迁移提示与可选云端向量库

## 参考项目取舍

### Bunny 原版

保留旧键兼容和简单易懂的条目编辑方式。原版角色分类、用户人设绑定、
世界书关键词、范围和优先级都是新版迁移的直接依据。

### 穗穗机

采用“角色绑定多本世界书”的直接交互。未照搬单 HTML 实现，
只为它的 `roles`、`worldBooks` 备份结构提供导入适配。

### 锁雾机

采用全局/角色范围、关键词、分组和注入位置的思想。其大型脚本和内部
DB 实现不直接复制，新版使用独立 TypeScript 类型和仓储层重写。

### SullyOS

采用统一 Context Builder、按最近消息触发世界书、按位置和顺序注入的
架构思想。由于上游是 PolyForm Noncommercial 1.0.0，本项目当前不复制
其实现代码；后续上下文构建器将独立实现并保留来源说明。

### CSY-OS

作为 React/TypeScript 应用分层、测试和 Capacitor 移动端封装的工程参考。
当前资料库阶段不引入其本地模型、3D、语音识别等重型依赖。

## 首轮风险

1. `openPage` 当前集中控制三十多个页面，是最大的导航耦合点。
2. 多个模块直接读写相同的 `localStorage` 键，不能边搬边随意改名。
3. 文件内出现重复的 `escapeHtml` 定义，拆分后需要收敛为共享工具。
4. API Key 当前保存在浏览器本地，导出/备份边界需要重新定义。
5. 聊天、自动总结、记忆注入互相包装原函数，迁移顺序必须固定。
6. `fab-custom.js` 缺失，悬浮球自定义能力暂时无法建立完整基线。

完成后再迁移拖拽，避免“导航、视觉、拖拽”三件事同时变化。
